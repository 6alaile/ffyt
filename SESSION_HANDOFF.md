# FFYT — Sub-Composition Fix: Session Handoff

## Status

We were working on a CI-render bug: the GitHub Actions workflow was producing videos where the text and voiceover rendered correctly but **all the stock video clips were missing** (flat dark frames behind the text). Root cause: the HTML the Python pipeline emitted for each scene was in the wrong HyperFrames shape, and the asset paths were also wrong.

This session rewrote `scripts/generate_html.py`. The **root-shape linter errors are fixed** but **font loading is still broken** (warnings remain). The fix has not yet been verified end-to-end in CI — only via `npx hyperframes lint hf_input/` locally.

## What was wrong

Two compounding bugs in the HTML emitted by `scripts/generate_html.py`:

1. **Sub-comps used the wrong HyperFrames pattern.** The skill (`C:\Users\PC\.claude\skills\hyperframes\SKILL.md:168`) is explicit: a file loaded via `data-composition-src` must have a `data-composition-id` and `data-width`/`data-height` on its root element, and the linter enforces this with `root_missing_composition_id` and `root_missing_dimensions` errors. The previous code put `id="hyperframes-root" data-composition-id="scene_NN"` on a div directly in `<body>`, which the runtime couldn't mount.
2. **Asset paths inside the sub-comp used `../assets/...`**, which assumed the sub-comp was a standalone file fetched from `compositions/`. When the runtime injects sub-comp content into the parent document, asset URLs are resolved against the parent (`hf_input/`), so `../` walked out of the project entirely and every video src 404'd.

The text rendered (it's all in the parent DOM), the audio worked (its path was already parent-relative), but the videos silently failed.

## What was changed in this session

All changes are in `scripts/generate_html.py`. The composition files (`composition.html`, `compositions/scene_*.html`) are regenerated by the script and are not hand-edited.

### 1. Deleted dead code (lines 527–811 in the previous file)

- `build_video_layer(scenes)` — generated `<video>` tags for a flat single-document composition. The CI never called it. Dead.
- `build_html(config, fmt, fmt_name)` — emitted a single HTML file with all scenes inlined. Also dead; `main()` writes the parent + per-scene files. The skill explicitly warns that the inlined pattern is wrong for sub-comps.

Both functions are removed. Don't recreate them.

### 2. Rewrote `build_scene_html()` (now around line 535)

**New shape:**

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>Scene N: {scene_id}</title>
    <style>
      /* full CSS for the scene, including :root, html/body, .display, .mono,
         #hyperframes-root, .scene, .scene-video, .scene-vignette, .scene-glow,
         .scene-content, .top-bar, .bottom-bar, all template-specific classes
         (.split-layout, .stat, .names, .counter-wrap, .host-grid, .nations,
         .badge, .subscribe-btn, .sub-bottom) + portrait overrides */
    </style>
  </head>
  <body>
    <!-- sub-composition root: MUST carry data-composition-id + data-width/data-height
         or the linter rejects this file with root_missing_* errors -->
    <div id="scene-NN"
         data-composition-id="scene_NN"
         data-width="{w}" data-height="{h}"
         data-start="0" data-duration="{scene.duration}">
      <video id="vid-scene1" class="scene-video"
        src="assets/clips/{scene_id}_processed.mp4" data-src="assets/clips/{scene_id}_processed.mp4"
        muted playsinline preload="auto"
        data-start="0" data-duration="{scene.duration}"
        data-track-index="0" data-scene="scene1"></video>
      <!-- scene content from tpl_*(scene, 1, fs), with {{START_1}} replaced by "0" -->
    </div>
    <script>
      window.__timelines = window.__timelines || {};
      window.__timelines["scene_NN"] = window.gsap
        ? window.gsap.timeline({ paused: true })
        : { paused: true };
    </script>
  </body>
</html>
```

**Critical details that are easy to break:**

- The **root is a plain `<div>`** in `<body>`, not inside a `<template>`. The skill's "sub-comp pattern with `<template>`" applies when the sub-comp is embedded by JavaScript in the parent; for `data-composition-src` file loads, the root needs to be a regular DOM element with `data-composition-id` + `data-width` + `data-height` on it.
- The video `src` is **`assets/clips/...`** (no `../`). Asset paths in the sub-comp resolve against the parent document (`hf_input/`), not the sub-comp's own URL.
- `clip_src(scene_id)` at the top of the file is the helper that emits `assets/clips/{id}_processed.mp4` — used as-is. Don't add `../` to it.
- The `<link rel="stylesheet" href="../assets/fonts/fonts.css">` that was in the previous version is **deliberately removed**. Re-adding it breaks the lint with `font_family_without_font_face` warnings (covered below in "What's still broken").
- The script is a **plain `<script>` in `<body>`**, not wrapped in `<template>` and not on `DOMContentLoaded` (the timeline doesn't need to wait for DOM, since it's a no-op paused timeline).
- The `tpl_fn(scene, 1, fs)` call uses `idx=1` (always 1 inside a sub-comp, since each sub-comp is its own root). The replace `{{START_1}} → "0"` is correct as-is.

### 3. Rewrote host divs in `build_parent_html()` (now around line 695)

Each host is now a single div with the full required attribute set on its own track:

```html
<div id="scene-NN-host"
     data-composition-id="scene_NN"
     data-composition-src="compositions/scene_NN.html"
     data-start="{t:.1f}"
     data-duration="{scene.duration:.1f}"
     data-track-index="{idx-1}"
     data-width="{w}"
     data-height="{h}"></div>
```

Notes:
- `data-track-index` is `idx-1` so scene 1 is on track 0, scene 2 on track 1, …, scene 8 on track 7. Voiceover audio is on track 8 (it's emitted at `data-track-index="{len(scenes)}"`).
- `class="clip"` was removed from the host divs and from the voiceover audio. The previous version had it; the skill doesn't require it and it was dead.
- The parent `<div id="hyperframes-root" data-composition-id="composition">` still exists at the top of the body and still registers `window.__timelines["composition"]`.

### 4. Cleaned up `main()`

- The `t_start` parameter was removed from `build_scene_html()`'s signature. It was previously computed but only used for the `{{START_1}}` replacement, which is now a hardcoded "0" inside the function. The cumulative-`starts` loop in `main()` was deleted as well — it's no longer needed.
- Print statement that uses the `✓` glyph: **wrap the print in `PYTHONIOENCODING=utf-8`** when running on Windows, or the script crashes with `UnicodeEncodeError` on `cp1252` consoles. The CI runs on Ubuntu so it doesn't hit this, but local Windows runs do. Fix once: either change the glyph to `OK` or set the env var. Lowest-friction: set `PYTHONIOENCODING=utf-8` in the local dev shell.

## What's still broken

After the rewrite, `npx hyperframes lint hf_input/` reports:

```
✗ [index.html] audio_src_not_found: <audio> references assets/audio/full_voiceover.mp3
✗ [index.html] missing_local_asset: <video> references assets/clips/*_processed.mp4 (8 files)
⚠ [compositions/scene_*.html] font_family_without_font_face: manrope, anton, jetbrains mono
```

**The two `✗` errors are expected locally** — `assets/clips/` and `assets/audio/` are empty on this machine (the CI's `Download Pixabay clips` and `Generate voiceover` steps populate them). In CI after the pipeline runs they will be present, so these errors won't fire. Don't try to fix them locally by stubbing the files; they're a real signal that clips/voiceover are missing, which is the whole reason this pipeline exists.

**The 8 `⚠` warnings are a real bug** that the next session needs to fix. The sub-comps reference `font-family: "Manrope"`, `"Anton"`, `"JetBrains Mono"` in CSS, but never declare `@font-face` rules pointing at the woff2 files in `assets/fonts/`. The previous version had a `<link rel="stylesheet" href="../assets/fonts/fonts.css">` which we removed, assuming the HyperFrames compiler would auto-embed the fonts. It doesn't — that only works for fonts on the compiler's allowlist (Inter, system-ui, etc.). For local custom fonts you must declare them.

### To fix the font warnings

The `assets/fonts/` directory contains `.woff2` files for Anton, Manrope, and JetBrains Mono, plus a `fonts.css` (the Google Fonts CSS that references those local files). Options for the next session:

**Option A (smallest diff): re-add the font link in each sub-comp, with the correct parent-relative path.**

In `build_scene_html()`'s `<head>`, before the `<style>` block:

```html
<link rel="stylesheet" href="assets/fonts/fonts.css" />
```

(no `../` — same reasoning as the video src: asset paths resolve against the parent document). The existing `assets/fonts/fonts.css` is the Google Fonts output that the previous code expected; verify it actually contains the `@font-face` declarations pointing at the local `.woff2` files (not just the Google CDN URLs). If it references CDN URLs, headless Chrome may fail to fetch them and the fonts still won't load.

**Option B (cleanest): inline the `@font-face` declarations into the sub-comp's `<style>` block.**

Add at the top of the sub-comp's `<style>`:

```css
@font-face { font-family: "Anton"; src: url("assets/fonts/Anton.woff2") format("woff2"); font-display: block; }
@font-face { font-family: "Manrope"; src: url("assets/fonts/Manrope-VariableFont_wght.woff2") format("woff2"); font-display: block; }
@font-face { font-family: "JetBrains Mono"; src: url("assets/fonts/JetBrainsMono-Regular.woff2") format("woff2"); font-display: block; }
```

(Use the actual filenames present in `assets/fonts/` — they're currently `1Ptgg87LROyAm3K8-C8QSw.woff2` for Anton and `tDbv2o-flEEny0FZhsfKu5WU4zr3E_BX0PnT8RD8yKwBNntkaToggR7BYRbKPx3cwhsk.woff2` for Manrope and similar for JetBrains Mono. The current names look like Google Fonts CDN cache filenames rather than friendly names. Either rename them to `Anton.woff2` / `Manrope.woff2` / `JetBrainsMono.woff2` or reference the full Google-Fonts names in the URL.)

After re-adding fonts, re-run `npx hyperframes lint hf_input/` and confirm the `font_family_without_font_face` warnings are gone.

## What I tried that didn't work (so you don't redo it)

- **`<template id="scene_NN-template">` wrapper around the sub-comp content.** The skill's `SKILL.md:168-189` example shows this pattern, and I implemented it in the first round. The linter rejected it with `root_missing_composition_id` and `root_missing_dimensions` because the linter validates the file as an entry composition and looks for the `data-composition-id` / `data-width` / `data-height` on the file's root DOM element, not on a `<template>`'s child. The fix was to drop the `<template>` and put the root `<div>` directly in `<body>`. The runtime is happy with this — it reads the body content and mounts it under the parent host div when the host's `data-start` window opens.
- **`<link rel="stylesheet" href="../assets/fonts/fonts.css">`.** Was in the original code. Removed in this session because the `../` was wrong (the sub-comp content is injected into the parent, so paths resolve against the parent). Re-add it (without `../`) only after confirming `assets/fonts/fonts.css` actually contains valid `@font-face` rules pointing at the local woff2 files.
